# vctrmemo — 実装ロードマップ（同期信頼性 → Vector対応 → Notion型製品）

更新日: 2026-10-23

## 0. 製品の前提と完成条件

- **製品目標**: Vector SDKと連携する、個人利用が第一のNotion型メモ・ページ・データベース。スマホとPCの**同じ1人**が利用し、別アカウントや別の参加者は要求しない。
- **非目標**: Vector本体を独自改修して利用者に特別なビルドを配ること。個人メモをチャット全参加者へ送ること。自動バックアップを同期の代わりとして完成扱いすること。
- **現行**: `https://badjoke-lab.github.io/vctrmemo/synced/` は**別のブラウザ版実験機能**。Vector Notesはリンクを保管するだけで、Vector Mini App内の動作ではない。本人のスマホ/PCでページ名と一部文章の相互同期が実測され、後続文章の同期遅延も報告された。
- **最新修正**: PR #10で入力中の送信抑止を解除、最後に開いたページを再読み込みで復元、「同期を停止」を再度押すと「同期を再開」に変わる。公開Nostrリレーを使用する自動ブラウザテストは成功。これでも本番品質・実機完全検証を主張しない。
- **本人認証**: 専用URLの `#k=` に含まれる共通の256-bit秘密鍵が、現状の閲覧/書込権限。Vectorアカウントの所有証明とは異なる。URL共有先は厳重に限定すること。
- **既存個人データ**: `vctrmemo-v2` の保存内容は勝手に移動・消去・公開しない。共同編集・共有は別機能として仕様承認後に実装。

## 実装順と各段階で利用者に見える挙動

### P0. 同期の正確性・到達保証とデータ保護（最優先）

**修正内容:** 送信待ちキューと操作IDの追跡、リレーの受理と**別端末の受信/適用確認（署名付きACK）**を分離。ローカル編集中・別端末からの受信・ブラウザ再読み込みが重なっても古い画面状態で新しい受信履歴を上書きしないよう、マージ処理とアプリ状態を一元化する。届かなかった操作を冪等に再送する。ページ・ブロックの追加/削除や複数行の編集を回帰試験。履歴の欠落・競合を検出した場合は危険な自動上書きを停止し、両方の版を保持する。

**具体的な動作:**
1. Macで文を打ち続ける → Macの画面は途切れず、内部キューに保存・送信される。入力欄からフォーカスを外す必要はない。
2. スマホが開いている → 暗号文の到着後にスマホ側が履歴を適用し、Macに「相手端末で反映済み」と返す。相手端末がオフラインなら「端末保存済み／相手未確認」のまま。
3. リレー障害 →「未送信（再試行）」と表示し、操作を捨てず復旧後に再送。既に届いた操作は重複させない。
4. Macで打っている途中にスマホで別の場所を編集 → 両方の変更を保ち、同じ項目を同時に変更した場合は少なくとも安全な競合として保護する。

**合格条件:** スマホとPCで分けて入力した100回以上の文章・ページ/ブロック追加/削除を、入力欄を開いたまま・順不同・重複配送・通信途絶を挟んでも消失させず、両端末の適用済み操作IDが一致する。画面の「送信済み」は受信確認と区別される。

### P1. 同期でページを再読み込みしない

**修正内容:** 受信時の `location.reload()` 依存を撤廃し、差分を現在のアプリ状態と表示へ反映する。自分の編集中のDOM、カーソル位置、IME変換、スクロール、表示ページは維持する。

**具体的な動作:** Macで「テスト」を入力すると、スマホが別ページを表示していてもページ一覧など必要な箇所が更新される。スマホで同じページを開いていれば該当ブロックが更新される。どちらも勝手にトップへ戻らない。別端末が同じブロックの編集中なら入力を上書きせず、安全な保留/競合通知を行う。手動リロードでも最後のページへ戻る。

**合格条件:** 長時間の相互編集でも自動ページリロード0回。選択中のページ・カーソル・入力途中の文字（日本語IMEを含む）を失わない。

### P2. 長期保存、オフライン、再接続・新端末復元

**修正内容:** 現状の公開Nostrリレーの通常イベント履歴（取得上限5,000件、ローカル操作履歴には別途上限）だけに依存しない、暗号化スナップショット＋差分ログ＋欠落範囲取得＋整合性確認を実装。永続保存先・負荷/無料枠・運用負担は比較/検証したうえで決定する。既存JSON書出し/読込みも維持。

**具体的な動作:** 飛行機モードでスマホに3行追加 →「端末保存済み／同期保留3件」表示。ネット復帰で自動送信 → Macに反映され「両端末で反映済み」。1週間スマホを開かなくても差分を回収できる。新しいPCで専用URLを開くと、ページ・DB・ブロックを整合性検証して復元する。データ保存先に障害があっても既存端末のメモを消さず、復旧操作を案内する。

**合格条件:** 長期の通信断・リレー削除・ページ数/履歴増加を想定した障害試験、復旧先の件数/内容/履歴ハッシュ一致、既存JSONとの互換性を検証する。公開リレーの保存期限が保証できない間は「完全復旧」を主張しない。

### P3. 安全な2端末登録、端末紛失対策

**修正内容:** 1人/1ワークスペースを保ちつつ、秘密鍵をURLで共有する現在の実験方式から、端末ごとの識別・権限・暗号化された登録、端末の失効、鍵の更新へ移行する。URL流出による権限奪取やブラウザ保存データの取り扱いを評価する。既存URLの突然の無効化やデータ消去はしない。

**具体的な動作:** 初回のPCでワークスペース作成 → スマホを1回登録 → 以後はそれぞれの端末で自動同期。登録端末一覧に「Mac」「スマホ」を表示。スマホを紛失したらMacから「スマホを無効化」を選ぶと、新しい同期鍵で以後の更新へのアクセスを止める（紛失前に取得されたデータは取り消せない）。機種変更は新端末登録＋暗号化履歴の復元で行う。

**合格条件:** 旧鍵で失効後の新しい同期データを取得/改変できない、登録端末以外の書込拒否、復旧・鍵更新中にもデータが欠けない。

### P4. Vectorの正式な利用体験（完成条件、並行して継続調査）

**現実の制約:** Vectorの現行Mini App sandboxでは外部WebSocketを直接使えず、同一アカウントのIroh実機診断もMac/スマホで同じNotes投稿を開いて送信15・応答0・受信0だった。WebXDCの履歴保存・配送APIも公式コードで未実装だった。ブラウザ版をVector Mini Appの完成品と言い換えない。

**具体的な利用体験の目標:** VectorのNotesにvctrmemoの**一つのリンク**を置く。Macで開いてメモした内容をスマホから同じ入口で開き、本人だけが閲覧/編集できる。メモをチャット全体に送信しない。リンクを毎回作り直さない。

**実装のゲート:** Vectorの**現行公式バージョン**のAPI/権限・認証・起動方式を追い、改造なしのMini App内双方向同期が可能であることを実機で証明できればMini App統合する。現行APIが不足するなら、Vector Notes→安全な外部ブラウザ利用は**明示した暫定手段**として継続し、Mini App完成扱いにはしない。Vector本体は勝手に改修しない。

**合格条件:** 本物のVector同一アカウント、Mac＋スマホで、本人以外への漏洩なしに実編集・オフライン復旧・保存継続を確認。単に2端末に同じWebページを開けた事実だけでは合格としない。

### P5. Notion型の使い勝手と品質

**修正内容:** 既存ページ階層・ブロック・DB表/ボード・検索・ページリンクを継続し、スマホUIの操作性、履歴/元に戻す、ページをすばやく開く、空状態、整理機能を順次磨く。個人利用に必要な動作を優先する。共同編集・ページ単位共有は本人同期と別の設計・許可として扱い、無断実装しない。

**具体的な動作:** Macでページ内に文章/チェック/DBレコードを追加するとスマホの該当ページに反映。スマホで完了チェックを付けるとMacのテーブル/ボードが更新。検索/ページ階層から目的のページへ移動しても編集途中を失わない。戻る/再読込でも同じページが開く。

**合格条件:** 実機のPC/スマホで主要フローに手動再読み込みが不要、ページ/DB/検索/リンクが一貫して動き、内容の消失やレイアウト崩れがない。

## 実施上の原則

- **順序:** P0 → P1 → P2 → P3 を基本に、P4の公式API調査と実機接続可否を並行して進める。その後P5の完成度を上げる。各段階のテスト・修正を確認してから公開。
- **完了判定:** CI成功、NostrリレーからOK、送信操作数、ブラウザプレビューだけでは完了としない。**相手端末で表示・保存まで行われた事実**を確認する。
- **公開の保護:** 大きな変更はPR＋新規/既存回帰テストで検証し、メモのデータキーや保存形式を無断変更しない。破壊的変更前にはバックアップと移行/ロールバックを用意する。
- **コスト:** まず無料枠・既存GitHub Pagesを優先。ただし無料公開リレーの無保証を製品の安全性と取り違えない。専用ストレージ/有料サービスが必要なら実装前に費用とデータ保護の条件を提示する。
- **用語:** 「端末保存済み」「リレー受理済み」「相手端末で受信済み」「相手画面に反映済み」を区別する。いまの「暗号化した変更を送信済み」は、**相手端末での反映を証明しない**。
- **開発範囲:** 対象リポジトリは `badjoke-lab/vctrmemo` のみ。Vector公式リポジトリへの変更は行わない。
